# MFA : QR et accompagnement — 16 septembre 2026

Le client reconnaissait uniquement un SVG commençant directement par `<svg`
ou une data URL SVG sans espace initial. Un SVG valide avec déclaration XML
ou commentaire pouvait donc laisser seulement la saisie manuelle visible.
Ce défaut est reproduit par les tests ; le format exact reçu par le navigateur
de l'utilisateur n'a pas été capturé et sa cause particulière reste à confirmer.

La conversion accepte maintenant les SVG avec préambule et les images SVG/PNG
embarquées. Les URL externes sont refusées : aucune clé MFA n'est transmise à
un service de génération de QR. L'image reste dans un élément `img`, sans injection
de SVG dans le DOM. Une erreur de chargement affiche la solution manuelle.

L'écran indique le compte administrateur protégé, les trois étapes de configuration,
des exemples d'applications TOTP et les paramètres de saisie manuelle. Il précise
que le code est généré dans l'application et non envoyé par email.

Validation : 147 tests applicatifs, 10 tests de rendu/composants, TypeScript,
lint et build réussis. Les tests ajoutés couvrent SVG brut, déclaration XML,
commentaires/doctype, data URLs, tailles excessives et refus des liens externes.
Pas de scan réel ni de validation AAL2 du compte utilisateur dans cette recette.
Pas de changement RBAC, de suppression SQL de facteur ni de contournement MFA.

Une clé de configuration partagée doit être remplacée avant activation. Pour un
enrollment encore non validé, l'implémentation existante expire son cache après
10 minutes ; une nouvelle connexion puis une nouvelle demande d'enrollment
remplace alors le facteur orphelin via Supabase Auth. Un rechargement avant
expiration peut reprendre la même clé et ne constitue pas une rotation.
