## Constats et limites

Dans Supabase : quatre migrations présentes, une organisation active ; un compte
invité confirmé avec mot de passe, mais aucun rôle administrateur actif au moment
du contrôle. Le programme `admin:grant` permet au développeur de choisir explicitement
le compte à autoriser. Aucun rôle réel ni mot de passe n’a été modifié pendant ce contrôle.

La capture du suivi correspond à `configured:false`, avant vérification du code.
Le contenu du fichier `.dev.vars` du développeur n’est pas accessible ici : variable
manquante, nom incorrect, serveur non redémarré ou mauvais répertoire restent à
départager par `backend:doctor` puis `/api/production/config`.

La destination exacte du lien d’invitation et les réglages Auth de redirection
n’ont pas pu être inspectés avec le connecteur disponible. Le code ne traite pas
les invitations email : la notice précédente annonçait un parcours incomplet.
La connexion par mot de passe du compte confirmé est la voie prise en charge.

Pas de test HTTP réel avec le mot de passe/TOTP du propriétaire, pas de vérification
de ses clés locales et pas de test natif iPhone. Les tests SQL de droits ne remplacent
pas ces essais. Aucun déploiement public réalisé dans cette intervention.
