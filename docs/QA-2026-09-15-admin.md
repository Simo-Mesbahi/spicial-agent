- L'écran administrateur explique la différence entre configuration locale et publiée.
- Le bouton de configuration indique « Préparation du QR code… » pendant la requête,
  annonce l'attente aux technologies d'assistance et reste protégé des doubles clics.
- L'enrollment dispose de 60 secondes côté navigateur, car il enchaîne plusieurs
  appels Auth limités individuellement à 10 secondes. Aucun POST n'est rejoué automatiquement.
- Une migration MFA absente retourne `mfa_storage_not_ready` (503), y compris lorsque
  D1 encapsule l'erreur SQLite. Aucun message brut de base de données n'est exposé.
- `backend:setup` marque explicitement sa configuration `.dev.vars` comme `LOCAL`,
  également quand elle est utilisée derrière l'adresse transférée d'un Codespace.
- MFA, cookies HttpOnly, contrôle AAL2, permissions et isolation restent obligatoires.

## Tester localement ou dans un Codespace

Depuis la racine du dépôt, utiliser Node.js >= 22.13. Arrêter l'ancien serveur avec
Ctrl+C. Si Git indique des changements personnels, les conserver ; ne pas utiliser
de reset forcé pour mettre à jour.

```bash
git switch main
git pull --ff-only origin main
node --version
npm ci
npm run backend:setup
```

L'assistant `backend:setup` demande l'URL, l'organisation et les deux clés Supabase.
Entrée conserve une clé déjà enregistrée ; saisir les clés seulement dans ce
terminal interactif, jamais en argument ou dans Git. Les valeurs proposées pour
l'URL et l'organisation correspondent au projet de préproduction fictif existant.
Ne pas activer un nouveau fournisseur LLM pendant la validation administrateur.

```bash
npm run db:migrate:local
npm run backend:doctor
```

Continuer seulement si le diagnostic confirme Auth accessible, clés reconnues,
organisation active et dossiers protégés. Puis :

```bash
npm run dev -- --port 5173 --strictPort
```

Le port strict évite d'ouvrir silencieusement un autre serveur. Si le port est occupé,
arrêter le serveur de ce projet déjà actif, puis relancer la commande.
Dans un second terminal du même environnement :

```bash
curl -sS http://localhost:5173/api/production/config
echo
curl -sS http://localhost:5173/api/production/health
echo
```

Résultats attendus : `configured: true`, `organizationConfigured: true`,
`environment: LOCAL`, puis `status: ok` et `database: reachable`.
Cela valide la configuration et la connexion, pas encore le MFA.

Ouvrir l'adresse affichée par Vite, puis `/admin`. Dans Codespaces, ouvrir le port
5173 depuis l'onglet Ports et garder cette même origine pour toutes les étapes.
Se connecter avec le compte existant, configurer ou reprendre l'authentificateur,
scanner le QR dans son application et saisir le code à six chiffres. Vérifier
l'ouverture de l'administration et le refus d'accès après déconnexion.
Ne pas recréer le compte administrateur ni supprimer son facteur par SQL.

Pour relancer les contrôles automatisés :

```bash
npm test
npm run typecheck
npm run lint:app
npm run build
npm run test:starter
```
