# Correction MFA administrateur — 14 septembre 2026

## Cause établie et limite du diagnostic

L’endpoint créait toujours un facteur avec le même friendly_name, sans consulter les facteurs existants. Après une création interrompue, un facteur unverified subsistait ; les répétitions pouvaient déclencher mfa_factor_name_conflict. Le gestionnaire global transformait les erreurs Auth en data_unavailable. L’interface affichait l’erreur uniquement dans le formulaire de code, invisible tant que l’enrollment avait échoué. Aucun mécanisme ne reprenait la préauthentification après actualisation.

Le fichier fourni par l’utilisateur est conservé : refresh_token opaque non vide et facteurs nullables, avec diagnostic de schéma sans valeurs. La logique du login fonctionnel n’est pas remaniée. La cause exacte du premier échec réseau ou de lecture de réponse ne peut être prouvée sans son code amont ; le facteur unverified prouve la création, pas la livraison du QR au navigateur.

## Correction

- API Auth /user pour l’état actuel, DELETE /factors/{id} pour abandonner uniquement les TOTP unverified nommés SAV SC Administration, puis POST /factors. Aucun SQL sur auth.mfa_factors, aucune suppression d’un facteur verified.
- Verrou D1 atomique par projet/utilisateur, partagé entre enrollment et vérification, avec bail de 90 secondes. Un appel concurrent reçoit mfa_in_progress ; une répétition après succès réutilise le même enrollment.
- QR/secret/URI chiffrés AES-GCM, liés au projet/utilisateur et à la préauthentification ; clé dérivée du secret serveur et du refresh token, jamais stockée. Validité logique de dix minutes, reprise uniquement dans la même préauthentification et si Supabase confirme le facteur unverified. Aucun secret dans localStorage ou les journaux. Effacement du contenu chiffré après vérification réussie.
- GET /admin/mfa/state permet la reprise après actualisation sans créer de facteur. Si le QR est irrécupérable, l’action explicite de configuration remplace le facteur abandonné via Auth.
- Erreurs MFA dédiées : conflit, facteur absent, MFA désactivé, code invalide, challenge expiré, préauth expirée, timeout, réseau et erreur Supabase 5xx. Un code TOTP périmé peut être signalé par Supabase comme mfa_verification_failed, identique à un code incorrect : l’application ne prétend pas pouvoir les distinguer.
- Erreur visible avant le QR, protection synchrone contre double clic, QR et secret manuel existants conservés, champ six chiffres et reprise explicite. Vérification challenge → verify → contrôle AAL2 → cookies HttpOnly inchangés.

## Validation exécutée

144 tests applicatifs réussis, dont six tests de parcours MFA avec un serveur Auth simulé : login 200/mfa_required, QR retourné, reprise, mauvais code, challenge/verify, AAL2 et cookies HttpOnly ; facteur abandonné ; appels concurrents ; autre préauthentification ; cache/préauth expirés ; erreurs amont distinctes. Les tests vérifient aussi l’absence du secret en clair dans D1 et de tokens dans la réponse JSON.

10 tests de rendu/composants réussis ; TypeScript, lint et compilation réussis. Migration D1 0004 générée et appliquée localement. Le scan physique Authenticator et le parcours navigateur authentifié sur le compte réel ne sont pas réalisés par ces tests. Aucun facteur du compte réel n’a été modifié pendant la recette.

## Installation et recette réelle

Après mise à jour du dépôt : npm run db:migrate:local puis npm run dev. Sur l’hébergement, appliquer aussi la migration D1 avant le nouveau Worker.

Se connecter normalement à /admin, choisir Configurer mon authentificateur, scanner le QR ou saisir le secret manuellement, entrer le code courant. Vérifier l’ouverture de l’administration. Actualiser pendant la configuration doit reprendre le même QR dans les dix minutes. Une tentative simultanée doit être refusée clairement, puis la reprise doit fonctionner. En cas de code incorrect, attendre le prochain code ; en cas de préauth expirée, se reconnecter. Ne jamais copier les secrets, cookies ou mots de passe dans un ticket ou dans la conversation.

Références : https://supabase.com/docs/guides/auth/auth-mfa et https://supabase.com/docs/guides/auth/debugging/error-codes
